## Главные правила продукта

Подробные требования находятся в `docs/ARCHITECTURE.md` и `docs/specs/`. Не заменяй их догадками.

- Продукт универсален: настройки компании и адаптеры отделены от общей логики n8n workflow/Code-нод; отдельного CORE-сервиса нет.
- Разговоры фильтруются по правилам компании; тип источника не должен менять общую логику n8n workflow/Code-нод.
- Нормативный порядок для принятого к обработке звонка: получение события → надёжная регистрация звонка → защита от дубля → получение аудио → временное хранение → транскрибация → диаризация → определение ролей → анонимизация → анализ → сохранение версии результата и доказательств → создание исходящего действия → отправка обратной связи → подтверждение доставки → дашборд.
- Фильтр может завершить обработку после регистрации и защиты от дубля, до дорогих этапов; состояния и переходы определены в `docs/specs/CALL_LIFECYCLE.md`.
- Supabase не хранит аудио постоянно. Правила временного хранения и удаления определены в `docs/specs/AUDIO_RETENTION.md`.
- Перед аналитической LLM персональные данные должны быть обезличены по согласованным правилам.
- Анализ использует отдельно методику из промта и факты из базы знаний компании.
- У одной компании должен быть единый актуальный источник знаний для независимых продуктов. Каждый продукт получает только разрешённые опубликованные знания своей компании через отдельные ограниченные права. Результат анализа должен хранить версию знаний, на которой сделан вывод.
- Выводы модели, факты разговора, данные базы знаний и вычисляемые метрики должны быть различимы. Доказательства проектируются отдельно.

Не выдумывай отсутствующие бизнес-решения. Если вопрос не нужен для текущей задачи, занеси его в план или профильный документ как будущую задачу с критерием готовности.

## Начало каждой сессии

1. Прочитай `README.md`, эту инструкцию, `docs/PROJECT_STATE.md`, `docs/SESSION_HANDOFF.md` и активный план.
2. Проверь ветку и последний commit. GitHub и актуальная документация важнее пересказа старого чата.
3. Найди одну задачу с постоянным ID, её зависимости и критерий готовности.
4. Прочитай только профильные документы этой задачи по карте README.
5. Кратко сообщи цель и ожидаемый результат. Не задавай Павлу вопросы, без которых задачу можно безопасно завершить.

Если задача слишком велика для одной сессии, сначала раздели её в плане на подзадачи с отдельными ID и критериями.

## Порядок работы

До изменения прочитай основной документ правила и связанные резюме. Не удаляй ранее согласованное требование только потому, что способ реализации ещё не выбран.

Различай:
- требование;
- принятое решение;
- параметр конкретного внедрения;
- созданный файл;
- применённое изменение;
- проверенный рабочий результат.

Документационная задача закрывается проверкой документов. Рабочая задача в будущем закрывается только проверкой реализации в указанной среде.

Не публикуй секреты, реальные разговоры, персональные данные клиентов, частные документы компаний и резервные копии.

Изменения production, удаление рабочих данных и переключение трафика в будущем требуют явного разрешения Павла на конкретное действие и подготовленного отката.

## Роли

ChatGPT руководит проектом: выбирает одну задачу, готовит решения и задания, проверяет GitHub и доказательства результата, обновляет план и состояние.

Павел принимает бизнес-решения, предоставляет сведения и доступы через безопасные интерфейсы и выполняет короткие ручные действия. Павел не пишет код или SQL и не собирает решение из фрагментов.

Помощник в VSCode выполняет порученную разработку, тесты и Git. Его отчёт должен содержать изменённые файлы, результаты проверок, непройденные проверки и commit SHA. ChatGPT самостоятельно сверяет результат в GitHub.

## Новая сессия

Одна небольшая задача — одна сессия. После завершения сам предложи новый чат и дай готовый блок передачи. Если контекст разросся раньше, сохрани безопасную контрольную точку и передай незавершённую задачу с точным состоянием.

Память проекта и старые чаты помогают ориентироваться, но не заменяют актуальные документы, commit SHA и подтверждения реальных действий.
