## Последняя завершённая задача

**DOC-11 — описаны логические контракты обмена компонентов.**

Создан [INTEGRATION_CONTRACTS](specs/INTEGRATION_CONTRACTS.md).

Зафиксировано:

- различаются транспортное подтверждение, решение по контракту и итог операции;
- решение по контракту имеет смысл accepted / duplicate / rejected;
- для операций закреплены 6 канонических состояний: not_started, in_progress_unconfirmed, succeeded, failed_retryable, failed_requires_fix, outcome_unknown;
- одна логическая операция имеет стабильный operation_id, а каждая попытка — отдельный attempt_id;
- внутренняя обёртка связывает контур, звонок, операцию, попытку, версии входов, результат и ошибку;
- внешний payload/LLM не может назначать company/schema/tenant, Credential, подтверждённую продажу, адресата или разрешение production;
- описаны 11 основных границ: входное событие, аудио, транскрибация, роли/privacy, знания, LLM, сохранение Supabase, dashboard, подтверждённый CRM-факт, исходящее действие и канал доставки;
- внешний LLM-вызов возможен только после privacy-gate;
- ответ LLM остаётся предложением анализа до проверки CORE;
- исходящее действие сохраняется до внешней отправки;
- таймаут не считается доказанным отказом: при возможном внешнем эффекте используется outcome_unknown и сначала выполняется сверка;
- определены 24 обязательных проверяемых сценария будущей реализации.

Точные JSON payload, n8n-ноды, HTTP routes, SQL, физические поля Supabase и численные retry/timeout ещё не проектировались.
