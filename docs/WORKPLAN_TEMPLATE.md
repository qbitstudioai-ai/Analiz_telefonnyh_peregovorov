Текущий режим — **только документация**. Этот план задаёт последовательность заполнения требований. Он не разрешает создавать SQL, workflow, код или менять сервер.

Одна небольшая задача — одна сессия. Статусы: `[ ]` не начато, `[~]` в работе, `[x]` проверено, `[!]` пауза.

## После документационной основы

Техническое проектирование n8n, Supabase, Whisper/диаризации, LLM и дашборда начинается только после DOC-19 и отдельного разрешения Павла.

На этом этапе отдельные задачи реализации намеренно **не проектируются**. Сначала документация должна определить требования и критерии, затем будущая сессия разложит реализацию на небольшие технические ID.

## В конце каждого ID

Обновить основной документ задачи, этот план и PROJECT_STATE. Проверить критерий, ссылки и противоречия. Сохранить commit, прочитать его из GitHub и подготовить handoff. Следующий чат начинает только один ID.
