# Источники разговоров и фильтрация

## Источники

Источник разговора зависит от конкретной компании.

Возможные варианты: Bitrix24, другая CRM, кабинет оператора связи, виртуальная АТС или другая система хранения записей.

## Входной адаптер

Входной адаптер должен получить сведения о разговоре, использовать доступные метаданные, применить правила отбора, при необходимости получить аудиозапись и передать дальше только разрешённый разговор.

Точный формат внутреннего пакета будет определён при проектировании workflow.

## Фильтрация

Разные компании могут хотеть:

- анализировать все рабочие разговоры;
- анализировать только продажи;
- анализировать определённые отделы;
- использовать уже отфильтрованные звонки из CRM;
- брать все записи оператора и исключать личные или ненужные разговоры.

Фильтрация должна быть частью изменяемых настроек компании.

## Простота настройки

Параметры фильтрации должны находиться в одном понятном месте.

Рабочее название блока: **НАСТРОЙКИ КОМПАНИИ — ФИЛЬТР ЗВОНКОВ**.

Павел при внедрении не должен искать условия по всему workflow.

Точный способ реализации — одна нода, отдельный блок переменных или другой вариант — определяется при проектировании n8n.

## Порядок фильтрации

Ненужные разговоры следует отсекать как можно раньше.

Предпочтительно сначала использовать метаданные: связь с CRM, направление, длительность, менеджера, отдел, теги и другие признаки.

Если метаданных недостаточно, допускается дополнительная классификация после транскрибации, но до полного анализа.

## Персональные данные

Если телефон, email, имя или другие персональные данные нужны только для фильтрации или сопоставления, их не следует без необходимости передавать дальше в CORE.
