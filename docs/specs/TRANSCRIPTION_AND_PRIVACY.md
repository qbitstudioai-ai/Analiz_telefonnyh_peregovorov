# Транскрибация, дикторы и анонимизация

## Транскрибация

Для анализа необходимо получить текст разговора.

Предварительно первым вариантом для испытаний выбран локальный/self-hosted Whisper.

Whisper не считается окончательно выбранным решением до тестов.

Испытания должны показать качество русской речи, пригодность для реальных телефонных записей, скорость и нагрузку на сервер.

## Разделение дикторов

Для качественного анализа необходимо понимать, кто произнёс каждую реплику.

Обязательные роли:

- МЕНЕДЖЕР;
- КЛИЕНТ.

Сплошного текста недостаточно.

Для будущих испытаний предварительно рассматриваются специализированные инструменты диаризации, например pyannote.audio и WhisperX.

Конкретный вариант выбирается после тестирования.

## Результат перед анализом

Перед аналитической LLM должен существовать структурированный диалог, где для реплик известны роль или технический speaker, текст и, если полезно, временные границы.

До анализа speaker-метки должны быть приведены к ролям `МЕНЕДЖЕР` и `КЛИЕНТ`.

Точный способ определения ролей проектируется позже.

## Анонимизация

До передачи транскрипции в аналитическую LLM должны быть скрыты персональные данные, которые не нужны анализу: телефоны, email, никнеймы, имена, адреса и другие идентифицирующие данные.

## Важная граница

Если транскрибация выполняется внешним сервисом, аудио может попасть внешнему провайдеру до анонимизации. Поэтому локальная или внешняя транскрибация оценивается отдельно при техническом проектировании.

## Аудиофайлы

Supabase не используется для постоянного хранения аудио. Правила временного хранения и удаления определяются позднее.
