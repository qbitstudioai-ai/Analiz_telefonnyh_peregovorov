# Правила ведения проекта

## Роли

### ChatGPT

Руководитель проекта: понимает план, выбирает следующую небольшую задачу, фиксирует решения, ставит задачи исполнителям, проверяет результат, обновляет документацию и предлагает переход в новую сессию.

### Павел

Куратор и исполнитель ручных действий. Павел принимает бизнес-решения и выполняет понятные инструкции. Он не должен самостоятельно писать SQL, код или собирать решение из разрозненных фрагментов.

### VSCode

Исполнитель задач разработки: код, файлы, тесты, Git, commit/push и деплой в разрешённом объёме.

## Одна задача — одна сессия

Работа выполняется небольшими блоками.

Документация GitHub должна позволять новой сессии продолжить работу без чтения всей старой переписки.

По мере развития проекта комплект будет дополнен отдельными документами для инструкции ChatGPT, рабочего плана, правил документации, передачи между сессиями, постоянных ID задач и критериев готовности.

## Глубина проработки

На этапе требований сначала фиксируются обязательное поведение, ограничения, настройки, CORE и решения, требующие испытаний.

Конкретные ноды n8n, SQL, библиотеки и внутренние форматы проектируются в будущих отдельных сессиях.

## Источник истины

Актуальная документация этого репозитория является главным источником истины для проекта.

Старый репозиторий бота используется только как образец и не изменяется.
