# DB-02 — транскрипция и privacy

Статус: SQL создан и статически проверен; **следующая migration для фактического применения в DB-08B**.

Зависимость: DB-01.

## Цель

Реализовать физическое разделение данных, зафиксированное DOC-07—DOC-09 и DOC-13:

- raw transcript;
- raw segments;
- versioned technical-speaker → business-role assignment;
- pseudonymized transcript;
- pseudonymized safe segments;
- privacy package и exact разрешённый segment set;
- reverse pseudonym mapping;
- processing quality;
- speech metrics.

## Файлы

- `supabase/migrations/002_transcription_privacy.sql`;
- `supabase/verify/002_transcription_privacy_verify.sql`;
- `supabase/rollback/002_transcription_privacy_rollback.sql`.

DB-02 использует schema `shablon_analiz_telefonnyh_peregovorov`, созданную DB-01.

## Физические сущности

Migration создаёт 11 таблиц:

1. `raw_transcripts`;
2. `transcript_segments`;
3. `role_assignment_versions`;
4. `role_assignments`;
5. `pseudonymized_transcripts`;
6. `pseudonymized_segments`;
7. `privacy_packages`;
8. `privacy_package_segments`;
9. `pseudonym_mappings`;
10. `processing_quality`;
11. `speech_metrics`.

## Главное privacy-разделение

### Raw transcript

`raw_transcripts` и `transcript_segments` содержат защищённый исходный текст локального российского контура.

Они имеют:

- exact call;
- version number;
- provenance модели/config;
- operation;
- audio metadata ref;
- validation/version state;
- retention policy;
- content hash;
- возможность удалить содержимое по retention, сохранив metadata.

### Role assignment

Technical speaker не перезаписывается бизнес-ролью.

`role_assignment_versions` задаёт immutable-by-version набор правил для exact raw transcript.

`role_assignments` хранит отдельно:

- technical speaker;
- business role;
- confirmed/assumed/undetermined;
- evidence types;
- trusted manager ref, если есть;
- conflict;
- manual correction metadata.

Недостоверно определённый speaker нельзя записать как manager/client при статусе `undetermined`.

### Pseudonymized transcript

`pseudonymized_transcripts` физически отделён от raw.

FK гарантирует, что:

- raw transcript принадлежит тому же call;
- role version относится именно к этому raw transcript и call;
- operation подготовки принадлежит тому же call.

`pseudonymized_segments` хранит safe text/timestamps/role, но exact raw source остаётся локальным через серверные FK.

### Reverse mapping

`pseudonym_mappings` — отдельная высокозащищённая таблица.

Она не входит в privacy package.

После retention deletion:

- `protected_value` должен быть NULL;
- `protected_local_ref` должен быть NULL;
- остаётся только metadata факта удаления/псевдонима в допустимой форме.

Конкретные DB roles/grants появятся в DB-07; до этого DB-02 не считается безопасно применённой runtime-схемой.

## Privacy package

`privacy_packages` хранит:

- exact pseudonymized transcript;
- exact role assignment version;
- privacy status;
- checker version;
- preparation operation;
- package hash;
- optional safe history ref;
- LLM operation provenance, если вызов разрешён;
- retention/version state.

### Критический инвариант

`privacy_packages` и `privacy_package_segments` не имеют прямых FK:

- на `raw_transcripts`;
- на `transcript_segments`;
- на `pseudonym_mappings`.

Exact разрешённый внешний transcript context задаётся через `privacy_package_segments`, которые могут ссылаться только на `pseudonymized_segments` того же pseudonymized transcript/call.

Пакет со статусом `blocked` не может иметь `llm_operation_id`.

## Версии

Для versioned сущностей добавлены:

- `version_no`;
- predecessor;
- `candidate/current/superseded/invalidated`;
- invalidation reason;
- provenance;
- частичные unique indexes на один current внутри семейства.

Семейства:

- raw transcript — call;
- role assignment — exact raw transcript;
- pseudonymized transcript — call;
- privacy package — call;
- quality — call;
- speech metrics — call.

Изменение содержимого должно создавать новую version по VERSIONING; DB-02 не вводит бесследное in-place исправление смысловых данных.

Retention deletion содержимого является отдельным допустимым изменением metadata/content availability и не превращает старую version в новую смысловую version.

## Processing quality

`processing_quality` отделена от manager score.

Хранит:

- audio/transcript/roles refs;
- quality rules version;
- audio/transcription/role technical metrics;
- `reliable/preliminary/technically_incomplete`;
- warning codes;
- operation provenance.

Preliminary/technically incomplete запись обязана иметь warning code.

## Speech metrics

`speech_metrics` хранит versioned derived параметры:

- manager/client talk ratio;
- pauses;
- interruptions;
- speech rate;
- duration;
- rules version;
- reliable/preliminary/unavailable.

Ненадёжные/недоступные metrics обязаны содержать warning code.

## Проверка после будущего применения

Порядок:

1. применить DB-01 migration;
2. применить `002_transcription_privacy.sql`;
3. запустить `002_transcription_privacy_verify.sql`;
4. verification создаёт только синтетические данные внутри транзакции;
5. в конце выполняется `ROLLBACK`, test rows не остаются.

Verification проверяет:

- наличие 11 DB-02 таблиц;
- отсутствие direct raw/mapping FK у privacy package;
- отсутствие raw/protected/mapping columns в package tables;
- создание raw transcript/segments;
- roles и запрет `undetermined → manager`;
- pseudonymized transcript/segments;
- reverse mapping как отдельную таблицу;
- passed privacy package и exact safe segment set;
- запрет LLM operation у blocked package;
- запрет сохранения reverse target после mapping retention deletion;
- composite operation+call ownership;
- processing quality;
- speech metrics.

## Rollback

`002_transcription_privacy_rollback.sql`:

- удаляет только DB-02 tables/types и добавленный DB-02 unique constraint DB-01 audio table;
- оставляет DB-01;
- отказывается работать при отсутствии ожидаемых DB-02 tables;
- отказывается работать, если в `shablon_analiz_telefonnyh_peregovorov` уже есть later/unknown table/view/materialized view.

После DB-03 rollback DB-02 этим файлом выполнять нельзя без отката зависимых migrations.

## Риски

- реальные PostgreSQL/Supabase execution tests ещё не выполнены;
- DB roles/grants/RLS ещё не реализованы — reverse mapping физически отделён, но фактическая runtime недоступность будет доказана в DB-07;
- plaintext `protected_value` допускается только как локальное защищённое поле до выбора конкретного encryption/secret-management решения; оно никогда не является внешним payload;
- retention jobs ещё не реализованы — DB-02 лишь хранит необходимые policy/deletion metadata;
- immutable semantics пока задаются version rows/constraints и будущими service operations; запрещённый SQL-admin может технически менять строки, поэтому ordinary runtime rights должны быть минимальны в DB-07;
- quality thresholds и реальные model metrics ещё не выбраны.
