# Архитектура продукта

Статус: требования верхнего уровня. Точная техническая реализация ещё не проектируется.

## Настройки компании

В одном понятном месте должны находиться параметры, которые обычно меняются при внедрении:

- источник разговоров;
- правила фильтрации;
- параметры компании;
- промт анализа;
- критерии оценки;
- подключённые выходные каналы.

Настройки не должны быть разбросаны по workflow.

## Адаптеры

Адаптеры связывают продукт с внешними системами: Bitrix24, CRM, кабинетами операторов, Telegram, MAX и другими системами.

Добавление нового адаптера не должно требовать изменения CORE.

## CORE

CORE выполняет общую обработку и анализ.

Настройки конкретной компании не должны жить внутри CORE.

CORE не должно зависеть от того, откуда пришёл разговор, какой оператор или CRM используется и куда отправляется обратная связь.

## Общий путь

Источник разговора  
→ входной адаптер  
→ фильтрация  
→ получение нужной записи  
→ транскрибация  
→ определение ролей менеджер/клиент  
→ анонимизация  
→ CORE анализа  
→ результат  
→ выходной адаптер для менеджера  
→ сохранение данных  
→ дашборд руководителя.

## Общая база знаний компании

База знаний компании должна рассматриваться как отдельный общий ресурс.

Если одна компания использует несколько продуктов QBit, желательно использовать один источник актуальных знаний: бот, анализ телефонных переговоров и будущие инструменты.

Продукты при этом остаются независимыми. Анализ телефонных переговоров не должен зависеть от workflow бота. Общим может быть слой знаний, но логика продуктов раздельная.

## Принцип внедрения

Новая компания должна подключаться преимущественно через настройки, адаптеры, собственные подключения, критерии оценки, промт и разрешённую базу знаний.

CORE при обычном внедрении не переписывается.
